# 우리의 10월

2026년 10월 1일~31일 팀 챌린지입니다. 정상 작동하는 `team-challenge-2026-september-sync-fix`의 디자인과 Google Sheets / Google Apps Script 저장 구조를 복사했습니다. 9월 프로젝트는 수정하지 않았습니다.

## 파일과 실행

- `index.html`: 화면, `window.CONFIG.syncUrl` 설정
- `style.css`: 기존 아이보리/딥그린 모바일 디자인, 31일 기록표
- `app.js`: 기록, 날짜 잠금, 벌금, 통계, 서버 동기화
- `Code.gs`: Google Apps Script 웹 앱 서버
- `README.md`: 설정과 배포 안내

`index.html`을 더블클릭하면 실행됩니다. VS Code에서는 이 폴더를 연 뒤 Live Server 확장을 설치하고 `index.html`을 우클릭하여 **Open with Live Server**를 선택해도 됩니다.

처음에는 `syncUrl`이 빈 문자열이므로 **이 기기에만 저장 중**으로 표시됩니다. 10월 기록과 임시 저장은 별도의 localStorage 키를 사용하며 9월 기록과 섞이지 않습니다. 공동 저장에는 아래 설정이 필요합니다.

## 참가자와 규칙

- 근제: 매일 매달리기 30초, 스쿼트 30개, 푸쉬업 30개, 등 스트레칭을 모두 완료해야 성공.
- 민경: 매일 30분 운동. 스쿼트는 고정이며 등 운동 또는 복부 운동 추가.
- 재선: 매일 수행, 헬스장 주 3회. 비헬스장 날은 집에서 스쿼트 50개. 재선에게만 헬스장 체크박스가 표시됩니다.
- 근도: 평일 푸쉬업 50개 또는 러닝 30분. 토/일은 자동 패스이며 벌금/성공률/개인 통계 집계에서 제외됩니다.

성공 `S`, 실패 `F`, 패스 `P`만 사용자가 선택합니다. 운동 선택 필드는 없습니다. 메모는 선택 입력, 최대 200자이며 저장 전에 앞뒤 공백을 제거합니다.

날짜 판정은 `Asia/Seoul` 기준입니다. 오늘과 어제만 입력/수정/비우기가 가능합니다. 미래와 기간 밖 날짜는 입력할 수 없습니다. 어제보다 이전 날짜는 잠기며, 기록이 없고 자동 패스 대상도 아니면 무단으로 확정됩니다. 무단은 시트에 저장하지 않고 앱에서 계산합니다.

실패 벌금은 2,000원, 무단 벌금은 3,000원, 성공/패스는 0원입니다. 성공률은 `성공 / (성공 + 실패 + 무단) × 100`이며 분모가 0이면 0%입니다. 오늘/어제 미입력과 미래 날짜는 제외합니다.

재선의 주간 방문 횟수는 월요일~일요일 중 `status: "S"`이면서 `gymVisit: true`인 기록만 집계합니다. 첫 주와 마지막 주는 해당 주의 10월 기간 안 기록만 집계합니다.

## 1. 새 10월 Google Sheets 만들기

1. Google Drive에서 **새로 만들기 → Google 스프레드시트**를 선택합니다.
2. 파일 이름을 **우리의 10월**로 정합니다. 9월 시트를 재사용하지 않습니다.
3. 시트 탭 이름을 **Records**로 바꿉니다.
4. 주소에서 `/d/`와 `/edit` 사이의 문자열을 복사합니다. 이것이 **스프레드시트 ID**입니다.

첫 행은 다음 순서입니다. 헤더가 없으면 서버가 자동 생성합니다.

```text
key | date | participantId | participantName | status | note | gymVisit | updatedAt
```

같은 날짜와 참가자는 `2026-10-10_geundo`처럼 `date_participantId`를 키로 사용하여 새 행을 추가하는 대신 수정합니다.

## 2. Apps Script 코드 설정

1. 새 10월 Sheets에서 **확장 프로그램 → Apps Script**를 클릭합니다.
2. 기본 `Code.gs`의 내용을 이 폴더의 `Code.gs` 전체 내용으로 교체합니다.
3. 코드 상단의 다음 값에 **새 10월 시트 ID**를 넣습니다.

```js
const SPREADSHEET_ID = 'PASTE_YOUR_GOOGLE_SHEET_ID_HERE';
```

4. 저장합니다. `SPREADSHEET_ID`에는 웹 앱 배포 ID나 시트 탭의 `gid`를 넣지 않습니다.

조회와 저장은 모두 동일한 `openById(SPREADSHEET_ID)` / `getRecordsSheet()`를 사용합니다. POST 저장은 행 추가/수정, `SpreadsheetApp.flush()`, 같은 시트에서 키 및 실제 필드 재검증을 마친 뒤에만 `ok: true`를 반환합니다. 웹 앱을 실행하는 계정은 새 시트의 편집 권한이 있어야 합니다.

## 3. 웹 앱 배포

1. Apps Script 우측 상단 **배포 → 새 배포**를 클릭합니다.
2. 톱니바퀴 **유형 선택 → 웹 앱**을 선택합니다.
3. 설명에 **october challenge api**를 입력합니다.
4. **다음 사용자로 실행 → 나**를 선택합니다.
5. **액세스 권한이 있는 사용자 → 모든 사용자**를 선택합니다.
6. **배포**를 누르고 실행 계정으로 권한을 승인합니다.
7. `/exec`로 끝나는 **웹 앱 URL**을 복사합니다.

## 4. syncUrl 설정

`index.html` 맨 아래의 설정에 새 URL을 넣습니다.

```html
<script>
  window.CONFIG = {
    syncUrl: "https://script.google.com/macros/s/새_10월_배포_ID/exec",
  };
</script>
```

페이지를 다시 열면 **팀 공유 켜짐 · 모든 기기 동기화**가 표시됩니다. 9월 웹 앱 URL을 넣으면 10월 기록이 거부되므로 새 10월 배포 URL을 사용합니다.

## 5. 공동 저장 점검

1. 브라우저에서 `새_웹앱_URL?action=list`를 엽니다. `ok: true`와 `records` 배열이 나오는지 확인합니다. `action=load`도 동일한 기록을 반환합니다.
2. 오늘 날짜에 근도 성공과 메모를 저장합니다. 주말이라면 다른 참가자로 테스트합니다.
3. 편집창은 즉시 닫히고 **저장 중...**이 표시됩니다. 서버가 실제 저장을 검증한 응답을 보낸 뒤에 **저장 완료**가 표시되어야 합니다.
4. Sheets **Records**에서 해당 날짜/참가자 행을 확인합니다.
5. 브라우저에서 **F5**를 누릅니다. 상태, 메모, 통계가 유지되어야 합니다.
6. 다른 휴대폰 또는 PC에서 같은 페이지를 열거나 **기록 새로고침**을 누릅니다. 같은 기록이 표시되어야 합니다.
7. 저장/조회 응답의 `spreadsheetId`, `sheetName`이 새 10월 시트와 **Records**인지 확인합니다.

기존 방식대로 페이지 로딩 및 **기록 새로고침**에서 전체 서버 기록을 불러옵니다. 저장 직후 전체 GET을 추가로 기다리지 않습니다. 자동 주기 조회는 추가하지 않았습니다. 연결 실패 시 이 기기 임시 저장을 유지하고, **기록 새로고침**에서 재연결과 미전송 기록 업로드를 시도합니다.

새 10월 서버는 직접 배포해야 하므로 배포 전에는 실제 Sheets 저장 및 다른 기기 조회를 검증할 수 없습니다.

## 6. GitHub Pages 배포와 공유

1. GitHub에서 새 10월 저장소를 만듭니다.
2. 새 `syncUrl`을 입력한 `index.html`, `style.css`, `app.js`를 저장소 루트에 업로드합니다. README도 함께 올릴 수 있습니다.
3. **Settings → Pages → Build and deployment → Deploy from a branch**를 선택합니다.
4. 브랜치와 폴더 **/(root)**를 선택하고 **Save**를 누릅니다.
5. 배포된 `github.io` 주소를 열고 저장 → F5 점검을 수행합니다.
6. 동일한 `github.io` 주소를 팀원에게 공유합니다.

`Code.gs`는 Apps Script에 넣는 서버 코드입니다. GitHub에 올리는 것만으로 서버 코드가 적용되지 않습니다. 웹 앱 URL을 아는 사용자는 별도 인증 없이 기록을 조회/수정할 수 있으므로 팀 안에서 공유합니다. 서버 전체 초기화 API는 없습니다.

## 서버 수정 후 재배포

Apps Script **저장 → 배포 → 배포 관리 → 현재 배포의 연필 아이콘 → 버전: 새 버전 → 배포** 순서로 진행합니다. 기존 배포를 업데이트하면 `/exec` 주소를 유지할 수 있습니다. 프론트 파일 수정은 GitHub Pages에도 업로드해야 합니다.

## 날짜 검증 예시

오늘이 한국 날짜 2026-10-10일 때:

- 10월 10일과 9일: 입력/수정 가능, 미입력은 무단 아님.
- 10월 8일: 수정 불가, 일반 참가자 미입력은 무단 3,000원.
- 근도 10월 10일/11일: 토/일 자동 패스, 벌금과 성공률 집계 제외.
- 실패 기록: 2,000원. 성공/패스: 0원.
- 재선: 성공 + gymVisit 체크 기록만 해당 주 방문 횟수에 포함.
- 9월 30일과 11월 1일: 기간 밖, 입력과 통계 제외.

11월 1일에는 10월 31일이 어제이므로 최종 입력이 가능합니다. 11월 2일부터 10월 전체가 마감됩니다. 서버 날짜 허용 범위는 10월 1일~31일이며, 오늘/어제 잠금은 기존 구조대로 앱 화면에서 적용합니다.

## JSON 백업

맨 아래 **JSON 내보내기**, **JSON 불러오기**, **로컬 기록 초기화**를 사용합니다. 파일명과 저장 키는 10월 전용입니다. 가져오기는 기존 방식대로 로컬 기록에 반영됩니다. 로컬 초기화는 Sheets 기록을 삭제하지 않으며, 연결된 서버 기록은 새로고침하면 다시 불러옵니다.
